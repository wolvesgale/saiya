Product Overview

催事販売管理

マルチテナント SaaS

催事の"裏方情報"をチームの資産に変える、売上ガバナンス付き管理プラットフォーム

⚠ 解く課題
課題①

催事会場の搬入時間・現金規定・ゴミ出しルールが担当者の頭の中にしかなく、 再開催のたびに調べ直し → 準備コスト増・ミス再発

課題②

日次売上が未入力になりがちで、手動督促が必要なため管理者工数が増える。締め時間を過ぎても誰も動かないケースが頻出

✓ 解決アプローチ
解決①

会場ごとの裏方情報をメモ・添付ファイルでデータ化。次回開催時は即アクセスで準備完了、ノウハウが組織資産に

解決②

21時締め・未入力を Cron で自動検知 → AWS SES で代理店に督促メール＋管理者同時通知。ガバナンスを仕組みで担保

主要価値 🏪 ナレッジ蓄積 📅 スケジュール運用 💰 売上習慣化 🔐 マルチテナント分離 📊 Google Sheets 連携 🔔 自動通知

主要ユーザーと権限

SuperAdmin

全テナント横断参照・システム管理。テナント制限なし

Admin

テナント内の全操作・メモ編集・売上確認・通知管理

Agent

担当イベントの売上入力・メモ追記（代理店名＋日時自動付与）

Broker

仲介業者（要件上想定・段階実装。Intermediary モデルは実装済み）

日次売上入力 & ガバナンス

実装済み
  • Agent がイベントページから当日売上を入力（金額・駐車場費・担当者名など）
  • 原則 21:00 締め — Cron が未入力イベントを検知し自動督促
  • 共有メモ — Agent は追記のみ（代理店名＋日時を自動付与）、Admin は全文編集
  • 売上データを Google Sheets へ 15 分間隔で自動同期（SalesRaw シート）
  • シート2に週次 / 代理店別 / 会場別集計を 2行/代理店 形式で自動書き込み
  • Admin 画面から手動で「スプシを更新」ボタンでも即時同期可能

通知 & アクセス管理

定期処理 / Cron Jobs（Vercel）

check-missing-sales 毎日 12:00 UTC

未入力イベントを検知 → MISSING_SALES 通知生成 + SES 督促メール一斉送信

check-unaccessed-events 毎日 12:05 UTC

開催2日前 + 未アクセスのイベントを検知 → 通知生成。Agent アクセス時に自動クローズ

sync-sales-to-sheets 15 分ごと

直近 90 日の売上を Google Sheets に同期。週次・代理店別・会場別集計を書き込み + 書式適用

マルチテナント & セキュリティ

  • 全モデルに tenantId を付与、クエリ時に自動スコープ
  • SUPER_ADMIN のみテナント横断参照が可能
  • セッション Cookie は HMAC-SHA256 署名で改ざん検知
  • PBKDF2 SHA-512（100,000 iterations）+ pepper でパスワード保護
